# CrashCart Merge Audit and Plan

Audit scope: base (`integration`, HEAD `105c5fa862ff779eff626099a5eb5273499abbf4`) and read-only reference (`master`, HEAD `1087ddbd3d570cc18a7bba43d3ffa54a8f0f24ef`). No tests or application commands were run during this audit. “Spec” below means `docs/BUILD_SPEC.md`.

## Interface mismatches and contract notes

| Boundary | Base implementation | Reference implementation | Spec contract / merge decision |
|---|---|---|---|
| Cross-repo Python interfaces | Existing tracked source is identical; all requested runtime modules are absent. | Same. | No observed base-vs-reference signature mismatch. Implement absent interfaces from the spec, with shared code contracts below. |
| LLM settings and credentials | `settings.api_key` resolves `LLM_API_KEY` then `NEBIUS_API_KEY`; `settings.base_url` reads `LLM_BASE_URL`. Roles include `reduce`, `baseline`, `swarm`, `eyes`, `skeptic`. | Identical. | Preserve these interfaces; spec calls baseline a tail baseline and requires role usage/prices. |
| LLM call return values | `call(role, messages, **kw) -> (response, latency_s)`; `call_stream(...)` yields `StreamDelta(text, usage)`. | Identical. | Later modules must adapt to this wrapper or deliberately standardize it in the reviewed plan. Role call and stream shape is not specified in the build spec beyond response plus latency and deltas plus final usage. |
| API/SSE event names | No API/event implementation in either repo. | Same. | Use spec names exactly: `run_started`, `baseline`, `tile`, `metrics`, `clusters`, `omni`, `narrative_token`, `verdict`, optional `skeptic`, `done`, `warning`, `error`; emit SSE `event:` names matching these. |
| API / data JSON fields | No runtime API implementation in either repo. | Same. | Follow Phase H route payloads and Appendix B result schema. Resolve any later implementation-specific additions without renaming spec fields. |
| Finding / evidence fields | Existing mock swarm emits `line_start`, `line_end`, `quote`, `kind`, `severity`, `why`; mock reduce returns `{narrative, result}` with Appendix-B-shaped abstention object. | Identical. | Align future verifier/cluster/swarm/reduce code to these source fields and spec citation fields (`file`, line range, quote). |
| Existing generator truth fields | `truth.json` test reads `category`, `evidence_file`, `evidence_line`; generator writes `fault_id`, location, dashboard flag and notes too. | Identical. | Keep this eval/test interface; truth must remain isolated to generator/eval and the truth-badge endpoint, never ingest/pipeline. |

## Features present in only one repo

- No unique application, test, tool, or documentation feature was found in either source tree; all project files that exist in both are identical.
- The reference repo alone tracks `.venv312/` (a Windows virtual environment containing installed dependencies). It is an environment artifact, not a feature, and must not be copied into the merged repo.
- The listed runtime modules and Dockerfile are absent from both, so there is nothing to port from the reference for those modules; the reviewed implementation will need to be built once from the spec in the base repo.
